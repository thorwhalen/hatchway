hatchway.mcp#

The second transport: a profile served as MCP tools, one tool per rule.

The SSH gate is the way in for an agent that can open SSH. An agent that speaks MCP but cannot (a claude.ai custom connector, Claude Desktop, another machine’s MCP client) gets the same allowlist here: each rule of the profile becomes one tool whose parameters are the rule’s flags and names, and every call is turned back into the request words and handed to a runner, which takes it through the gate. So the same decide(), the same log, the same gated classes, the same one-call-at-a-time lock, whichever way it arrived.

>>> from hatchway.policy import Profile
>>> p = Profile.from_dict({"rule": [{"match": ["crowsnest", "triage"],
...     "argv": ["crowsnest", "triage"], "flags": ["-q", "--quiet"]}]})
>>> calls = []
>>> tools = mk_tools(p, runner=lambda req: calls.append(req) or Result(0, "ok", ""))
>>> [t.__name__ for t in tools]
['crowsnest_triage']
>>> tools[0](quiet=True)
'ok'
>>> calls
['crowsnest triage --quiet']

The runner is the seam. local_runner() (the default) runs the gate on this machine; ssh_runner() sends the request over SSH to a key whose forced command is the gate, which is how a process running as its own account reaches a machine’s tools without holding any of their credentials. Building the server needs fastmcp (pip install 'hatchway[mcp]'); nothing else in hatchway imports it.

hatchway.mcp.fan_out(runners, *, label=<function tag_lines>, is_down=<function unreachable>, deadline=25.0, ttl=30.0, clock=<built-in function monotonic>)[source]#

Ask every runner at once and merge their answers, each part labelled with its name.

Where with_fallback() asks a second machine only when the first is down, fan_out asks all of them, for questions every machine answers about itself (its own sessions). The parts come back in the order of runners, each through label (default tag_lines()). A part that could not be reached, was refused, was busy, failed, or took longer than deadline seconds does not fail the call: it is named on a line of its own at the end, so the reader knows whose answer is missing rather than reading a partial list as whole. A part that answered nothing is named too.

The call fails only when no part answered: then the status is a refusal if any part refused, else the first part’s that reached its machine, and the error names every part.

The merged answer is reused for ttl seconds for the same request, so a long answer read page by page (offset) does not shift under the reader. ttl=0 turns it off. Only use fan_out for reads: a request that changes something must go to one runner.

>>> up = lambda r: Result(0, "busy  a\n", "")
>>> down = lambda r: Result(UNREACHABLE, "", "ssh: connect to host x: Operation timed out")
>>> print(fan_out({"mac": down, "tw": up})("crowsnest roster").out, end="")
[tw] busy  a
[mac] (did not answer: ssh: connect to host x: Operation timed out)
